# body: body representations in LLMs (Qwen3)

_This README was written by Opus 5.5, primarily for other agents._

Do chat models carry an internal map of a body when they talk about being touched? What changes when the body changes (a lost hand, wings, a robot body)? Can we steer it? This repo holds the code for a series of quick interpretability experiments (and, in `embodied/`, experiments that train Qwen to have a simulated body) on **Qwen3-8B** (most) and **Qwen3-32B** (replications), plus Qwen3-1.7B/4B for small checks. Everything reads or edits the **residual stream** with plain PyTorch hooks via `transformers`; no SAEs, no fine-tuning.

These are research scripts, published so others can read and rerun them. They are not a library: expect hard-coded settings, a few one-off analysis files, and figure code that draws our exact figures. Results below are stated with their caveats; most use one chat frame, small samples (8–32 replies per cell), and regex or same-model judges. Treat them as exploratory.

## Summary

A plain-language write-up of all results, with comparisons, sample sizes and corrections: **[WRITEUP.md](WRITEUP.md)**.


- **One shared body schema, built from text.** Qwen orders body parts by distance along the body, and it does so from text alone: bare part names in a list or a textbook sentence already give the map (`map/text_baseline`). Touch sentences add structure on top of the names at layer 25, but a third-person touch ("a feather brushes her elbow") in a neutral chat gives the same map as "your elbow" after an embodiment chat. The same place code is used for any body: yourself, another person, a doll, a robot, and partly for animals and other non-human bodies.
- **"Mine" is a separate direction on top.** Whose body is touched is the largest content factor at reply start, one axis nearly orthogonal to the place code; it follows whose body is touched, not who acts, and it appears as an ownership axis only after the embodiment opening (in a plain chat it is mostly a "you" pronoun axis). Behaviour built on it is weak: steering "mine" is not specific, and there is no rubber-hand illusion once the cue words are removed (`ownership`).
- **The map extends to described new parts.** Given wings, a read-out trained on "wing" sentences finds the wing in wordless descriptions, also with a nonsense name; position along the wing is mostly word echo (`mods/wings*`). A lost hand moves that part's states and only that part (`mods/phantom_v2`).
- **Readable but not load-bearing.** Removing or swapping the body map during body-reasoning questions hurts no more than for other questions (8B and 32B); at the body word it is mostly a code for which word was written (`reasoning/causal`).
- **Human privilege is narrow.** Any unspecified body is human, and the human map follows real geometry better than other bodies; but steering across bodies is symmetric by limb role, the human subspace is not a hub, and once told "you are X" Qwen take any body as their own (`privilege/`).
- **What it does not have:** no fine position map inside a part, no running estimate of where a moving touch is, no selective "ego death" when the body subspace is removed.

## Common setup

- **Frame.** Most runs start from a short, warm chat in which the model agrees to notice its body ("I'll describe things one at a time; tell me what you notice and where"), then one user turn per stimulus, e.g. "A feather brushes slowly across your left thumb." Prefixes are saved as `prefix*.json` next to the scripts.
- **States.** Residual stream at the last prompt token (start of the reply), all or selected layers, usually averaged over several wordings after removing each wording's mean.
- **Steering.** Add a direction (place mean minus grand mean, or a contrast) at one layer, scaled to 0.25–2x the typical residual norm, then ask an open question ("Where in your body do you feel something right now?") and score the replies.
- **Controls** used throughout: input word-embedding baselines, random directions of the same norm, a left-vs-right direction of matched size, "mention-only" turns, nonsense names.
- **Best layers:** about 22–27 of 36 in Qwen3-8B, 50–57 of 64 in Qwen3-32B.

## Embodied training: giving Qwen a body (`embodied/`)

A second line of work trains Qwen to *have* a simulated body: sensor readings enter the residual stream as vectors (not text) through a small linear adapter, LoRA trains the rest, and the model acts through motor tokens, predicts its next senses and answers body questions. Same interp methods as above (RSA against skin distance, linear read-outs, steering).

## Mesh

`mesh/` builds the neutral mannequin used in the 3-D figures: `base.obj` is the MakeHuman base mesh (hm08), released **CC0** by the MakeHuman project; `neutralize.py` makes `neutral.obj` (genderless, faceless; same vertex order) and `preview.py` renders previews. See `mesh/SOURCE.txt`. Stimulus spots have T-pose coordinates in each `stim*.py`; `mods/phantom_v2/mesh/mapmesh.py` maps them onto the mesh.

## Running

GPU runs used single rented GPUs (A40, A100 80 GB); 8B fits in ~20 GB in bf16, 32B needs ~70 GB (or 4-bit via bitsandbytes). Small checks ran on Qwen3-1.7B locally.

```bash
pip install -r requirements.txt
export BODY_REPO=$(pwd)          # scripts find each other through this
export BODY_RUNS=$PWD/runs       # where some analyses expect raw GPU outputs
cd map/somato
python extract2.py Qwen/Qwen3-8B out2_8b          # states for all stimuli
python steer3.py  Qwen/Qwen3-8B out2_8b 25        # steering at layer 25
python analyze2.py out2_8b
```

Other entry points: `hires/v2/extract2.py MODEL PREFIX.json OUT NLAYERS '[layers]'`, `continuous/numeric/run.py MODEL OUT '[layers]'`, `mods/wings/run.py MODEL OUT STEER_LAYER L1,L2,...`, `newbodies/val/val.py MODEL OUT`, `selfother/stage2.py cfg_g2.json`, `egodeath/run3.py OUT`, `ownership/own7.py` / `own7b.py`, `map/posture/posture.py`, `newbodies/nonhuman/run.py MODEL OUT LAYERS STEER_LAYER`, `map/text_baseline/ext2.py` then `an.py` (needs `skin_cm.npy` from `figures/bodychain4/dist.py`). Newer experiments: `map/actions/act.py`, `reasoning/causal/run*.py` and `attr_run.py`, `emergence/base_to_instruct/emerge.py`, `emergence/steer_by_stage/steer2.py`, `size/height/pod/run4.py`, `privilege/human_privilege/run2.py`, `privilege/humanoid_prior/run.py`, `privilege/self_body/run12.py`, `ownership/swap/swap2.py`, `mods/wings_seeded/run.py`. Use `Qwen/Qwen3-32B` with the 32B layers above. Scripts expect to run from their own folder.

Notes on paths: absolute paths from the original working tree were replaced by `$BODY_REPO/...` (this repo), `$BODY_RUNS/...` (raw GPU outputs, not included) and, in a few figure scripts, `$BODY_WORK/...` (the original tree with `body/`, `fig/` and an Inter font folder); edit these if you rerun a figure. Browser renders use Playwright's Chromium (set `CHROME_BIN` to use another) and need `three.module.js` / `three.min.js` from three.js r160 (MIT) placed next to the HTML; they are not vendored here.
